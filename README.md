# 로보틱스 AI 1주차 · 로봇 제어와 임베디드 입출력

## 이번 주에 배운 내용

- **로봇의 판단**: 카메라와 라이다로 장애물을 찾고, 목적지까지 갈 경로와 목표 속도를 정한다.
- **바퀴의 제어**: MCU가 짧고 일정한 주기로 실제 속도를 읽고 모터 출력을 보정한다.
- **입출력 실습**: Ubuntu에서 코드를 보드에 올리고, 버튼과 가변저항 입력을 LED 밝기와 서보 각도로 연결한다.

## 1. 로봇의 자동성과 동작 과정

### 1-1. 로봇의 기원과 자동성

- **기원**: 체코어 *robota*는 강제 노동을 뜻한다. 카렐 차페크의 1920년 희곡 \*R.U.R.\*에서는 사람을 대신해 일하는 존재를 로봇이라고 불렀다.
- **자동성**: 사람이 동작을 하나씩 지시하지 않아도 맡은 일을 수행하는 성질이다.
- **세탁물 예시**: 세탁기는 정해진 순서로 세탁한다. 로봇 팔이 세탁물을 건조기로 옮기려면 옷의 위치를 읽고, 잡을 곳을 정하고, 그 위치까지 팔을 움직여야 한다.

### 1-2. 복도에서 상자를 만났을 때

| 단계               | 로봇이 하는 일                                     |
| ---------------- | -------------------------------------------- |
| ① 인지(Perception) | 센서로 상자 위치와 통로 폭을 읽고, 로봇의 현재 위치와 바퀴 속도를 확인한다. |
| ② 계획(Planning)   | 상자 양옆의 공간을 비교해 충돌 없이 목적지까지 갈 경로를 고른다.        |
| ③ 제어(Control)    | 양쪽 바퀴 속도를 바꿔 회전하고, 실제로 얼마나 돌았는지 확인한다.        |

- **폐루프(closed loop)**: 측정 결과를 다음 명령에 반영한다. 덜 돌았으면 모터 출력을 고치고, 새 장애물이 나타나면 경로를 다시 정한다.
- **시뮬레이션**: 같은 명령을 실물에 적용하기 전에 예상 이동 경로를 확인할 수 있다.

## 2. High-level 판단과 Low-level 제어

### 2-1. High-level Decision Making: 어디로 갈지 정한다

1. **인식**: 카메라와 LiDAR로 주변을 살피고 지도에서 현재 위치를 추정한다.
2. **계획**: 목적지까지의 경로를 정한다. 앞이 막혔으면 우회 경로를 고른다.
3. **주행(Navigation)**: 경로를 따라가기 위한 목표 전진 속도와 회전 명령을 하위로 보낸다.

### 2-2. Low-level Control: 바퀴가 명령대로 움직이게 한다

1. **모터**: MCU가 모터 드라이버에 PWM 신호를 보내 바퀴를 돌린다.
2. **엔코더**: 일정 시간 동안 바퀴가 회전한 양을 읽어 실제 속도를 구한다.
3. **피드백 제어**: PID 등의 방식으로 목표 속도와 실제 속도의 차이를 줄인다. 오르막에서 속도가 떨어지면 모터 출력을 높인다.

### 2-3. 두 단계의 제어 주기와 개발 환경

**제어 주기**: 측정과 출력 갱신을 반복하는 시간 간격.

| 구분        | High-level                    | Low-level                   |
| --------- | ----------------------------- | --------------------------- |
| 중요한 요소    | 영상·지도 처리에 필요한 연산 성능과 메모리      | 정해진 시간에 측정하고 출력을 갱신하는 실시간성  |
| 주기가 다른 이유 | 장면과 실행 중인 작업에 따라 계산 시간이 달라진다. | 상위가 계산하는 동안에도 바퀴는 계속 움직인다.  |
| 주기 예시     | 100 ms마다 목표 전달(10 Hz)         | 10 ms마다 속도 보정(100 Hz)       |
| 장치        | 노트북·서버 또는 SBC                 | MCU(실습 보드 ESP32 D1 R32)     |
| 언어        | Python, C++                   | C, C++                      |
| 운영체제      | Linux(Ubuntu)                 | RTOS로 주기 작업 관리              |
| 소프트웨어     | ROS 2                         | 제어 펌웨어, 상위 통신에 쓰는 micro-ROS |

**예시를 읽는 방법**: 상위가 목표 속도를 한 번 보내면 하위는 그 목표로 약 10번 보정한다. 새 목표가 도착하면 다음 하위 제어 주기부터 그 값을 쓴다.

### 2-4. SBC와 MCU

- **SBC(Single Board Computer)**: 프로세서·메모리·입출력 장치를 한 기판에 갖춘 컴퓨터. Raspberry Pi나 Jetson에서 Linux를 실행해 영상·지도·AI 모델을 처리할 수 있다.
- **MCU(Microcontroller Unit)**: CPU·메모리·GPIO·타이머·ADC를 한 칩에 갖춘 제어 장치. ESP32나 Arduino Uno R3의 AVR 칩에서 센서를 읽고 모터 출력을 갱신한다.

## 3. 로봇의 인식과 AI

### 3-1. 규칙 기반 제어와 학습 기반 판단

- **규칙 기반**: “앞의 거리가 일정 값보다 작으면 정지”처럼 조건과 동작을 사람이 정한다.
- **학습 기반**: 여러 영상에서 공통 특징을 학습한다. 조명이나 방향이 바뀌었을 때 물체를 알아보는 데 쓸 수 있다.
- **적응형 행동**: 관측한 상황이 달라지면 로봇도 행동을 조정한다.

### 3-2. “책상 위 빨간 컵을 집어 줘”라는 지시

| 모델                          | 입력          | 이 예시에서 하는 일               |
| --------------------------- | ----------- | ------------------------- |
| LLM(Large Language Model)   | 언어 지시       | 대상은 빨간 컵이고 동작은 집기라고 해석한다. |
| VLM(Vision-Language Model)  | 지시 + 카메라 영상 | 영상에서 지시가 가리키는 컵을 찾는다.     |
| VLA(Vision-Language-Action) | 지시 + 관측     | 팔의 이동과 그리퍼를 닫는 동작을 출력한다.  |

- **멀티모달**: 영상·텍스트·음성처럼 형식이 다른 정보를 함께 다룬다.
- **Embodied AI**: 몸을 가진 에이전트가 행동하고 다시 관측하는 과정을 다룬다. 가상 환경의 로봇도 포함한다.
- **Physical AI**: 센서로 실제 환경을 읽고, 판단 결과를 구동기의 물리적 행동으로 연결한다.

### 3-3. SLAM, 3D 지도와 활용

- **SLAM(Simultaneous Localization and Mapping)**: 복도에서 같은 벽과 모서리를 여러 번 관측하며 **로봇의 위치와 지도**를 함께 추정한다.
- **지도 표현**: 2D 지도는 평면 주행에, 3D 지도는 높이와 표면 표현에 쓴다. Neural Map은 공간 정보를 신경망에 학습시킨다.

| 활용              | 입력이 결과로 이어지는 과정                                                |
| --------------- | -------------------------------------------------------------- |
| 컴퓨터 비전 · 3D 재구성 | 여러 시점의 2D 영상에서 카메라 위치와 3D 구조를 추정한다.                            |
| 그래픽스 · 디지털 트윈   | 3D 장면을 특정 시점의 2D 화면에 투영한다. 실제 설비를 복원해 가상 공간에 반영할 때도 좌표 변환을 쓴다. |
| 점검 로봇           | 접근하기 어려운 곳에서 정상 상태와 현재 관측을 비교하고, 이상을 발견한 지도 좌표를 기록한다.          |
| AR 내비게이션        | 카메라 위치와 방향에 맞춰 영상 위에 경로를 그린다. 위치 추정이 틀리면 화살표도 통로에서 벗어난다.       |

## 5. Ubuntu에서 ESP32에 프로그램 올리기

### 5-1. Arduino IDE 실행 준비

1. **실행 파일 배치**: 수업에서는 Arduino IDE 실행 파일을 `/opt` 아래에 둔다.
2. **실행 스크립트 작성**: 첫 줄의 `#!/bin/sh`는 해석할 셸을 지정하는 쉬뱅이다. 다음 줄에 IDE의 실제 경로를 적는다.
3. **명령 등록**: `chmod +x`로 실행 권한을 준다. `PATH`에 있는 폴더에 `ln -s`로 심볼릭 링크를 만들면 어느 폴더에서나 이름으로 실행할 수 있다.

### 5-2. 보드 연결부터 업로드까지

1. **연결**: 데이터 전송용 USB 케이블을 연결하고 `/dev/ttyUSB0` 또는 `/dev/ttyACM0` 등 실제 포트 이름을 확인한다. 끝 번호는 달라질 수 있다.
2. **보드와 포트 선택**: IDE에 ESP32 보드 패키지를 설치한다. **D1 R32**는 컴파일 대상, **포트**는 업로드 대상을 정한다.
3. **권한 오류가 뜰 때**: `ls -l /dev/ttyUSB0`처럼 실제 포트의 소유 그룹을 확인한다. 그룹이 `dialout`이면 `sudo usermod -aG dialout "$USER"`로 사용자를 추가하고 다시 로그인한다.
4. **업로드와 확인**: 스케치를 컴파일해 보드에 올린 뒤, 같은 포트의 시리얼 모니터에서 출력값을 확인한다.

## 6. 임베디드 시스템과 전기 기초

### 6-1. MCU의 입력과 출력

- **임베디드 시스템**: 특정 기능을 수행하도록 설계한 시스템. 자동차의 후진 경고 장치는 센서가 읽은 거리에 따라 경고음을 낸다.
- **GPIO(범용 입출력 핀)**: 버튼을 읽을 때는 입력, LED를 켤 때는 출력으로 설정한다.
- **공통 GND**: 센서와 MCU의 GND를 연결해 같은 지점을 0 V로 삼는다. 그래야 센서의 출력 전압을 MCU도 같은 기준에서 읽는다.

### 6-2. 폭포로 이해한 옴의 법칙

| 기호 | 회로에서의 의미    | 폭포에 비유하면           |
| -- | ----------- | ------------------ |
| V  | 전압 · 볼트(V)  | 위아래 수면의 높이 차       |
| I  | 전류 · 암페어(A) | 한 지점을 1초에 지나는 물의 양 |
| R  | 저항 · 옴(Ω)   | 물길을 좁혀 흐름을 방해하는 돌  |

- **관계식**: `V = IR`. 높이 차가 같아도 물길이 좁아지면 흐름이 줄듯이, 같은 전압에서는 저항이 클수록 전류가 줄어든다.
- **계산**: 저항 양단이 3 V일 때 `3 V ÷ 1 kΩ = 3 mA`. 저항을 2 kΩ으로 늘리면 1.5 mA다.
- **LED 회로**: LED와 220 Ω 저항을 직렬로 연결해 과전류로 인한 손상을 막는다.

### 6-3. ESP32의 전원 핀과 신호 핀

| 표시             | 역할                                                             |
| -------------- | -------------------------------------------------------------- |
| GND / VCC      | 기준 전위 0 V / 부품에 공급하는 전원                                        |
| 5V / 3V3 / VIN | 5 V 전원 / 3.3 V 전원 / 외부 전원 입력. VIN 허용 범위는 보드 사양에 따른다.           |
| GPIO / ADC     | 디지털 상태를 읽거나 출력 / 연속 전압을 정수로 읽기. ESP32 가변저항 입력은 3.3 V 범위로 구성한다. |
| PWM            | 출력 가능한 핀에 할당한다. Uno에서 물결표(`~`)는 PWM 지원 핀을 뜻한다.                 |

### 6-4. 코드에서 핀 전압까지

1. `pinMode(pin, OUTPUT)`: 방향 레지스터를 설정해 핀을 출력으로 쓴다.
2. `digitalWrite(pin, HIGH)`: 출력 상태를 정하는 비트가 바뀌고 실제 핀 전압이 올라간다.
3. **칩별 차이**: AVR 계열은 방향 레지스터를 DDR이라고 부른다. ESP32는 다른 레지스터 구성을 쓴다. ADC 설정과 변환 결과도 레지스터로 다룬다.

**Uno LED 점멸**: D7 → 저항 → LED → GND로 연결한다. 핀 번호를 상수로 두면 배선이 바뀌어도 한 곳만 수정하면 된다.

```cpp
const int ledPin = 7;

void setup() {
  pinMode(ledPin, OUTPUT);   // 시작할 때 한 번만 출력 핀으로 설정
}

void loop() {
  digitalWrite(ledPin, HIGH);
  delay(1000);               // 1초 동안 켬
  digitalWrite(ledPin, LOW);
  delay(1000);               // 1초 동안 끔. 한 주기는 2초
}
```

## 7. 버튼 입력과 시리얼 통신

### 7-1. 풀업과 풀다운

**플로팅**: 버튼을 떼어 접점이 열렸을 때 입력 핀의 전압이 잡음에 따라 흔들리는 상태. 저항으로 기본 상태를 정해 이를 막는다.

| 회로             | 버튼을 뗐을 때             | 버튼을 눌렀을 때     | 눌림을 알아보는 변화 |
| -------------- | -------------------- | ------------- | ----------- |
| 풀업(Pull-up)    | 저항을 통해 전원에 연결 → HIGH | GND에 연결 → LOW | HIGH → LOW  |
| 풀다운(Pull-down) | 저항을 통해 GND에 연결 → LOW | 전원에 연결 → HIGH | LOW → HIGH  |

- **입력 읽기**: `digitalRead(pin)`으로 현재 상태를 확인한다.
- **내부 저항**: ESP32에서 지원하는 핀은 `INPUT_PULLUP` 또는 `INPUT_PULLDOWN`으로 설정할 수 있다.

### 7-2. 필기의 파란 선은 무엇인가?

| 구분     | 버튼을 한 번 눌렀을 때                                               |
| ------ | ----------------------------------------------------------- |
| 핀 전압   | 풀다운 회로의 전압이 0 V에서 전원 전압까지 짧은 시간에 걸쳐 올라간다. 파란 선은 이 연속적인 변화다. |
| 디지털 입력 | MCU는 전압이 어느 범위에 있는지에 따라 LOW 또는 HIGH로 읽는다.                   |
| 바운싱    | 기계 접점이 여러 번 붙었다 떨어져 한 번 누른 동작이 여러 번으로 읽힐 수 있다.              |
| 디바운싱   | 입력이 일정 시간 안정된 뒤 한 번만 센다. 버튼으로 LED를 켰다 끌 때 필요한 처리다.          |

### 7-3. 시리얼 모니터에서 확인할 것

- **시리얼 통신**: 한 비트씩 순서대로 보내는 직렬 통신.
- **보드레이트(baud rate)**: 초당 전송하는 심볼 수. 실습 UART는 한 심볼이 한 비트라서 115200 baud가 115200 bit/s에 해당한다.
- **속도 설정**: `Serial.begin(115200)`이면 모니터도 115200에 맞춘다. 9600도 자주 쓰는 설정이다.
- **출력 함수**: `Serial.print()`는 같은 줄에 이어 쓰고, `Serial.println()`은 출력 후 줄을 바꾼다.

## 8. 가변저항, ADC와 PWM

### 8-1. 가변저항의 위치를 숫자로 읽는 순서

1. **배선**: 양끝을 전원과 GND에 연결하고 가운데 단자의 전압을 읽는다.
2. **전압 분배**: 손잡이를 돌리면 양쪽 저항의 비율이 달라진다. 5 V를 걸고 두 저항이 같으면 가운데는 약 2.5 V다.
3. **ADC 변환**: 그래프의 가로축은 시간, **세로축은 전압**이다. 8비트 ADC는 세로축을 256칸으로 나눠 0부터 255까지 번호를 붙인다. 같은 칸에 들어온 전압은 같은 정수로 읽힌다.

| 필기·실습 구분                | ADC가 돌려주는 정수 | 구간 수  |
| ----------------------- | ------------ | ----- |
| 필기에서 생각한 8비트 ADC        | 0\~255       | 256   |
| Arduino Uno R3의 10비트 입력 | 0\~1023      | 1,024 |
| 실습 ESP32의 12비트 입력 설정    | 0\~4095      | 4,096 |

- **해상도**: 1비트는 0 또는 1, 8비트는 1바이트다. n비트 ADC는 전압 범위를 `2^n`칸으로 나누므로 비트 수가 클수록 한 칸의 전압 폭이 좁아진다.
- **DAC**: 디지털 값을 아날로그 전압으로 바꾼다. 실습의 클래식 ESP32는 GPIO 25·26에 8비트 DAC가 있다.

### 8-2. PWM 듀티비

**듀티비(%) = 한 주기에서 HIGH인 시간 ÷ 전체 주기 × 100**

| 한 주기 | HIGH인 시간 | 듀티비  | LED 동작        |
| ---- | -------- | ---- | ------------- |
| 4 ms | 0 ms     | 0%   | 계속 꺼짐         |
| 4 ms | 1 ms     | 25%  | 주기의 1/4 동안 켜짐 |
| 4 ms | 2 ms     | 50%  | 절반 동안 켜짐      |
| 4 ms | 4 ms     | 100% | 계속 켜짐         |

- **밝기 조절**: PWM은 핀의 HIGH/LOW를 빠르게 반복한다. 켜지는 비율이 커질수록 LED가 밝아진다. 50%는 **시간**의 비율이고 눈에 보이는 밝기와는 차이가 있을 수 있다.
- **출력값**: ESP32의 PWM을 8비트로 설정하면 명령 범위는 0\~255다. DAC는 주어진 값에 대응하는 아날로그 전압을 출력한다.

### 8-3. 손잡이를 절반쯤 돌렸을 때

`analogRead()`로 입력을 읽고 `map()`으로 출력 범위에 맞춘다.

| 실습            | 입력 핀·범위                     | 출력 핀·범위                    | 손잡이 중간 예시                    |
| ------------- | --------------------------- | -------------------------- | ---------------------------- |
| Uno · LED 밝기  | A2 · 0\~1023                | D9 · PWM 0\~255            | 512 → 127(정수 계산) → 약 50% 듀티비 |
| ESP32 · 서보 각도 | GPIO 39 · 0\~4095, 3.3 V 기준 | GPIO 14 · 0\~180°에 대응하는 펄스 | 2048 → 목표 각도 90°             |

**Uno 실습 코드**: 시리얼 모니터에는 A2의 입력값이 찍히고, LED에서는 변환된 출력이 밝기로 보인다.

```cpp
void setup() {
  pinMode(9, OUTPUT);
  Serial.begin(115200);
}

void loop() {
  int raw = analogRead(A2);
  int brightness = map(raw, 0, 1023, 0, 255);
  analogWrite(9, brightness);
  Serial.println(raw);
  delay(50);
}
```

## 9. 로봇 PCB 키트의 센서와 구동기

### 9-1. 센서가 읽는 물리량

| 부품           | 측정값      | 읽는 방법                                                    |
| ------------ | -------- | -------------------------------------------------------- |
| IMU 가속도계     | 세 축의 가속도 | 정지해 있어도 중력의 영향이 나타나 기울기 추정에 쓸 수 있다.                      |
| IMU 자이로스코프   | 세 축의 각속도 | 로봇이 어느 축을 중심으로 얼마나 빠르게 회전하는지 본다.                         |
| 지자기 센서       | 지구 자기장   | 방향 추정에 활용한다. 실내 금속·전자기기의 영향을 받으며, IMU 모듈에 따라 포함 여부가 다르다. |
| 회전형 2D LiDAR | 방향별 거리   | 키트에서는 360°를 스캔해 각도와 거리로 장애물의 윤곽을 구한다.                    |

### 9-2. 서보와 버저에 보내는 신호

| 부품     | 배선                             | 출력으로 정하는 것                     |
| ------ | ------------------------------ | ------------------------------ |
| 서보 모터  | 갈색 GND · 빨간색 5 V · 노란색 GPIO 14 | HIGH 펄스의 **폭**으로 목표 각도를 정한다.   |
| 피에조 버저 | 키트의 GPIO 5                     | 구동 신호의 **주파수**로 경고음의 높낮이를 정한다. |

- **서보 타이밍**: 일반적인 취미용 서보는 약 20 ms 주기(50 Hz)를 쓴다. 실제 각도 범위와 허용 펄스 폭은 제품에 따른다.
- **서보 전원**: GPIO 14는 각도 명령을 보내고 구동 전류는 전원선이 공급한다. 별도 전원을 써도 MCU와 서보의 GND를 연결한다.
- **LED와 서보 비교**: 같은 손잡이 위치를 읽어도 LED는 한 주기 중 켜진 **시간 비율**을, 서보는 목표 각도에 대응하는 **펄스 폭**을 바꾼다.
