## 1. 로봇은 어떻게 판단하고 움직일까?

**인지 → 계획 → 제어**: 복도에 상자가 있으면 센서로 위치를 파악하고, 지나갈 경로를 고른 뒤, 양쪽 바퀴 속도를 바꿔 회전한다. 센서로 다시 확인한 결과가 다음 판단과 제어에 쓰인다.

- **자동성**: 사람이 동작을 하나씩 지시하지 않아도 맡은 일을 수행하는 성질. 수업에서는 정해진 순서로 도는 세탁기와, 옷의 위치를 직접 찾아 건조기로 옮기는 로봇 팔을 비교했다.

### High-level Decision Making: 어디로 갈지 정한다

1. **인식**: 카메라와 LiDAR로 주변을 살피고 지도에서 현재 위치를 추정한다.
2. **계획**: 목적지까지의 경로를 정한다. 앞이 막혔으면 우회 경로를 고른다.
3. **주행(Navigation)**: 경로를 따라가기 위한 목표 전진 속도와 회전 명령을 하위로 보낸다.

### Low-level Control: 바퀴가 명령대로 움직이게 한다

1. **모터**: MCU가 모터 드라이버에 PWM 신호를 보내 바퀴를 돌린다.
2. **엔코더**: 일정 시간 동안 바퀴가 회전한 양을 읽어 실제 속도를 구한다.
3. **피드백 제어**: PID 등의 방식으로 목표 속도와 실제 속도의 차이를 줄인다. 오르막에서 속도가 떨어지면 모터 출력을 높인다.

### 둘의 제어 주기가 다른 이유

상위에서는 영상의 복잡도와 Linux에서 함께 실행 중인 작업에 따라 계산 시간이 달라진다. 하위에서는 그동안에도 바퀴가 움직이기 때문에 엔코더를 읽고 출력을 갱신하는 간격을 일정하게 유지해야 한다.

| 구분 | High-level Decision Making | Low-level Control |
| --- | --- | --- |
| 중요한 요소 | 인식·판단에 필요한 처리 성능과 메모리 | 제때 측정하고 출력을 바꾸는 실시간성 |
| 주기 예시 | 100 ms에 한 번 목표 갱신(10 Hz) | 10 ms에 한 번 속도 보정(100 Hz) |
| 장치 | 노트북 또는 SBC(예: Raspberry Pi, Jetson) | MCU(예: ESP32) |
| 사용 언어 | Python, C++ | C, C++ |
| 운영체제 | Linux(Ubuntu) | 실시간 작업을 관리하는 RTOS |
| 소프트웨어 | ROS 2 | 제어 펌웨어, 상위와 통신하는 micro-ROS |

**두 주기를 맞추는 방법**: 위 숫자는 주기 차이를 이해하기 위한 예시다. 상위가 100 ms마다 목표 속도를 보내면 하위는 같은 목표를 기준으로 10 ms마다 약 10번 보정한다. 새 목표가 오면 다음 보정에 반영한다. 이렇게 하면 상위의 판단이 늦어져도 하위의 제어 간격을 유지할 수 있다.

## 2. 로봇의 인식과 AI

- **SLAM**: 센서로 같은 벽과 모서리를 여러 번 관측하면서 로봇의 위치와 주변 지도를 함께 추정한다. 만든 지도는 이동 경로를 정하는 데 쓴다.
- **지도와 활용**: 2D 지도는 평면 주행에, 3D 지도는 높이와 표면을 표현하는 데 쓴다. 점검 로봇은 이상을 발견한 위치를 지도에 남기고, AR 내비게이션은 카메라의 위치와 방향에 맞춰 경로를 겹쳐 그린다.
- **규칙 기반과 학습 기반**: 전방 거리가 기준보다 작으면 멈추는 것은 사람이 정한 규칙이다. 조명이 바뀐 영상에서도 같은 컵을 찾아내는 데에는 학습한 특징을 쓸 수 있다.

| “책상 위 빨간 컵을 집어 줘” | 역할 |
| --- | --- |
| **LLM** | 문장에서 대상이 빨간 컵이고 동작이 집기라는 점을 해석한다. |
| **VLM** | 언어 지시와 카메라 영상을 함께 보고 어느 컵을 가리키는지 찾는다. |
| **VLA** | 지시와 관측을 바탕으로 로봇 팔과 그리퍼의 행동을 출력한다. |

- **멀티모달**: 영상·언어처럼 형식이 다른 정보를 함께 다루는 것. 몸을 가진 에이전트가 관측하고 행동하는 과정을 Embodied AI라고 하며, 실제 센서와 구동기를 통해 물리 환경에 작용하는 사례로 Physical AI를 살펴봤다.
- **3D 재구성과 디지털 트윈**: 여러 시점의 영상에서 공간 구조를 추정하고, 실제 설비를 가상 공간에 재현한다. 공간 자체를 신경망에 학습시키는 Neural Map도 지도 표현의 한 예다.

- **장비에 맞는 구성**: 오픈소스 드라이버와 로봇 라이브러리를 조합할 수 있다.

## 4. 임베디드 시스템과 전기 기초

- **임베디드 시스템(Embedded System)**: 특정 기능을 수행하도록 설계한 시스템. 수업에서는 MCU가 센서를 통해 주변을 인식한 뒤 LED·모터 같은 출력 장치를 작동시켜 물리적 환경과 상호작용했다. 후진 경고 장치가 거리를 읽고 소리를 내는 것이 한 예다.
- **GPIO(General Purpose Input/Output)**: 입력으로 설정하면 핀의 전압 상태를 읽고, 출력으로 설정하면 HIGH 또는 LOW를 내보낸다.
- **공통 GND**: 센서와 MCU가 같은 지점을 0 V로 삼도록 GND를 연결한다. 그래야 센서가 보낸 전압을 MCU도 같은 기준으로 읽는다.

### 폭포로 이해한 옴의 법칙

| 기호 | 회로에서의 의미    | 폭포에 비유하면           |
| -- | ----------- | ------------------ |
| V  | 전압 · 볼트(V)  | 위아래 수면의 높이 차       |
| I  | 전류 · 암페어(A) | 한 지점을 1초에 지나는 물의 양 |
| R  | 저항 · 옴(Ω)   | 물길을 좁혀 흐름을 방해하는 돌  |

- **관계식**: `V = IR`. 높이 차가 같아도 물길이 좁아지면 흐름이 줄듯이, 같은 전압에서는 저항이 클수록 전류가 줄어든다.
- **계산**: 저항 양단이 3 V일 때 `3 V ÷ 1 kΩ = 3 mA`. 저항을 2 kΩ으로 늘리면 1.5 mA다.
- **LED 회로**: LED와 220 Ω 저항을 직렬로 연결해 과전류로 인한 손상을 막는다.

### 디지털 · 아날로그 · ADC

- **디지털**: 입력 전압을 LOW 또는 HIGH로 구분해서 읽는다. **아날로그**: 센서의 출력 전압처럼 중간값을 가지며 연속적으로 변한다.
- **ADC(Analog-to-Digital Converter)**: 연속적인 전압을 정수로 바꾼다. 필기 그래프에서 가로축은 시간, 세로축은 전압이다. **8비트**라면 세로축의 전압 범위를 256칸으로 나누고, 측정한 전압이 들어간 칸의 번호를 0부터 255까지로 읽는다.
- **보드에 따른 범위**: Uno의 10비트 ADC는 0~1023,실습 ESP32의 12비트 설정은 0~4095다. **DAC**는 반대 방향인 디지털 값 → 아날로그 전압 변환이다.

## 5. Tinkercad 실습 · Uno LED 점멸

**Uno LED 점멸**: D7 → 220 Ω 저항 → LED → GND로 연결한다. 핀 번호를 상수로 두면 배선이 바뀌어도 한 곳만 수정하면 된다.

```cpp
const int ledPin = 7;

void setup() {
  pinMode(ledPin, OUTPUT);   // 시작할 때 한 번만 출력 핀으로 설정
}

void loop() {
  digitalWrite(ledPin, HIGH);
  delay(1000);               // 1초 동안 켬
  digitalWrite(ledPin, LOW);
  delay(1000);               // 1초 동안 끔. 한 주기는 2초
}
```
