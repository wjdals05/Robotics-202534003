- ESP32가 IMU의 가속도·각속도는 I²C로 요청해서 읽고, LiDAR의 거리값은 UART로 받아 오는 과정을 배웠다.

- ROS 2에서 노드가 토픽으로 메시지를 주고받는 구조를 보고, 거북이 시뮬레이터와 Python의 Talker·Listener 예제로 확인했다.

## 1. 센서와 MCU는 어떻게 통신할까?

| 구분 | UART | I²C |
| --- | --- | --- |
| 통신 방식 | 비동기식. 양쪽이 전송 속도와 프레임 형식을 미리 맞춘다. | 동기식. SCL의 클록에 맞춰 SDA로 데이터를 주고받는다. |
| 연결 | 보내는 쪽의 TX를 받는 쪽의 RX에 연결한다. | 여러 장치가 SDA와 SCL을 공유하고, MCU가 주소로 장치를 고른다. |
| 수업 예시 | LiDAR가 보내는 거리 패킷을 ESP32가 수신한다. | ESP32가 IMU의 레지스터를 지정해 측정값을 요청한다. |

- **Baud rate**: 클록 선을 따로 쓰지 않는 UART에서는 양쪽에 같은 값을 설정한다. 필기에 적은 예시는 `9600`과 `115200`.
- **8N1**: 한 프레임에 데이터 8비트, 패리티 없음(N), 정지 비트 1개를 사용한다.
- **I²C의 신호 구분**: SCL이 HIGH일 때 SDA가 HIGH → LOW로 바뀌면 START, LOW → HIGH로 바뀌면 STOP이다. 데이터 비트를 보낼 때는 SCL이 HIGH인 동안 SDA 값을 유지한다.
- **ACK / NACK**: 한 바이트를 보낸 뒤 9번째 클록에서 수신 측이 응답한다. SDA를 LOW로 당기면 ACK, HIGH로 두면 NACK이다. MCU가 마지막 바이트를 읽고 전송을 마칠 때도 NACK을 쓴다.
- 필기에는 다른 임베디드 통신 방식으로 SPI와 차량에서 쓰는 CAN도 나왔다.

## 2. IMU 값과 LiDAR 거리 읽기

### IMU: I²C로 어느 값을 읽을지 지정한다

1. **측정값**: 가속도계는 세 축의 선가속도를, 자이로는 세 축의 각속도를 측정한다. 필기의 ‘나침반’은 지자기 센서에 해당한다. 이날 코드에서 읽은 값은 가속도·온도·각속도였다.
2. **초기화**: 실습 보드의 SDA는 GPIO 21, SCL은 GPIO 22다. `Wire.begin()`으로 I²C를 시작하고, 전원 관리 레지스터에 값을 써서 센서의 절전 모드를 해제한다. PC에 값을 출력하는 통신은 `Serial.begin()`으로 따로 연다.
3. **읽기**: 측정값이 시작되는 레지스터를 지정한 뒤 **14바이트**를 요청한다. 순서는 가속도 6바이트 → 온도 2바이트 → 자이로 6바이트. 온도를 출력하지 않아도 가운데 2바이트를 읽어야 자이로 값의 위치가 맞는다.
4. **값 복원**: 한 축의 값은 2바이트다. 상위 바이트를 왼쪽으로 8비트 이동한 뒤 하위 바이트와 OR 한다. 즉, `(상위 바이트 << 8) | 하위 바이트`로 한 축의 원시값을 조립한다.

### LiDAR: UART로 들어오는 패킷을 해석한다

- **데이터 경로**: LiDAR의 TX → ESP32의 RX. 센서 데이터를 받는 시리얼 포트와 PC의 시리얼 모니터에 출력하는 포트를 구분한다.
- **패킷**: 수업 장치에서는 47바이트가 한 묶음이다. 헤더로 시작을 확인하고 시작·끝 각도, 측정 지점별 거리와 신뢰도를 읽는다. 거리 1개는 2바이트, 신뢰도는 1바이트다.
- **각도**: 패킷에 들어온 정수 각도를 100으로 나눠 도 단위로 복원한다. 장애물이 로봇의 앞에 있는지 판단하려면 LiDAR의 장착 방향과 로봇의 전방을 먼저 맞춰야 한다.

## 3. 모터 드라이버와 장애물 회피

| IN1 | IN2 | 수업에서 사용한 드라이버의 동작 |
| --- | --- | --- |
| HIGH | LOW | 정방향 회전 |
| LOW | HIGH | 역방향 회전 |
| HIGH | HIGH | 제동. 바퀴가 돌기 어렵다. |
| LOW | LOW | 구동 해제. 바퀴가 자유롭게 돈다. |

- 바퀴 하나에 입력 2개, 네 바퀴에 총 8개를 사용한다.
- **회피 판단 예시**: 전방 거리값을 읽고, 앞이 비면 전진한다. 장애물이 가까워지면 멈추거나 회전하도록 바퀴 명령을 바꾼다. 이때 ‘어떤 조건에서 방향을 바꾸는지’를 의사코드로 표현한다.

## 4. ROS 2와 통신 환경

- **ROS 2**: Ubuntu 위에서 로봇 프로그램을 개발하는 소프트웨어 프레임워크. 하드웨어의 세부 차이를 공통 인터페이스로 다루고, 인식·연산·제어를 담당하는 프로그램들이 데이터를 주고받도록 한다. 기능은 패키지 단위로 재사용한다.
- **ROS 1과 ROS 2**: ROS 1은 중앙의 Master에 노드와 토픽을 등록한다. 수업에서 사용한 ROS 2는 DDS로 통신 상대를 자동 발견하고 직접 데이터를 주고받는다. 보안 설정과 QoS도 지원한다.
- **실습 환경**: Ubuntu 24.04 LTS(Noble Numbat)와 ROS 2 Jazzy. 수업에서는 DDS 구현체로 Cyclone DDS를 사용하도록 설정했다.
- **Domain ID**: 같은 네트워크에서 어느 노드끼리 서로 발견할지 나누는 번호. 기본값은 `0`, 내 실습 번호는 `13`이다. 터미널마다 값이 다르면 같은 컴퓨터에서 실행한 Talker와 Listener도 서로 발견하지 못한다.

```bash
# Ubuntu의 Bash 터미널
source /opt/ros/jazzy/setup.bash  # 현재 터미널에 ROS 2 환경 적용
echo "$ROS_DISTRO"                # jazzy인지 확인
export ROS_DOMAIN_ID=13           # 현재 터미널을 실습 도메인 13으로 설정
echo "$ROS_DOMAIN_ID"             # 다른 실습 터미널도 같은 번호인지 확인
```

## 5. 노드 · 토픽 · 메시지

| 용어 | 수업 예시로 이해하기 |
| --- | --- |
| **노드(Node)** | 한 가지 역할을 맡는 실행 단위. 카메라 영상을 받는 노드, 연산하는 노드, 바퀴를 제어하는 노드로 나눌 수 있다. |
| **토픽(Topic)** | 이름이 붙은 데이터 통로. 라디오에 비유하면 채널이고, `/turtle1/cmd_vel`은 첫 번째 거북이의 속도 명령 채널이다. |
| **메시지 / 타입** | 메시지는 실제로 보낸 값, 타입은 그 값의 구조다. `String`의 문자열은 `data`에, `Twist`의 전진 속도는 `linear.x`에 들어간다. |
| **Publisher / Subscriber** | 방송국처럼 토픽에 값을 발행하는 쪽과 라디오처럼 그 토픽을 구독하는 쪽. 토픽 이름과 메시지 타입이 맞아야 한다. |

- **중첩된 메시지**: `Pose`는 위치(`position`)와 방향(`orientation`)을 담는다. `TwistStamped`는 `header`와 `twist`를 묶어서 속도뿐 아니라 시각과 기준 좌표계도 전달한다.
- **QoS(Quality of Service)**: 같은 토픽이라도 무엇을 전달하는지에 따라 규칙을 고른다.

| 기준 | 설정 | 수업에서 든 예시 |
| --- | --- | --- |
| 신뢰성 | **Reliable** | 놓친 데이터를 재전송한다. 정지 명령처럼 누락되면 곤란한 경우. |
| 신뢰성 | **Best Effort** | 유실을 허용한다. 이전 측정값보다 최신 값이 중요한 LiDAR 데이터. |
| 지속성 | **Volatile** | 구독을 시작한 뒤 발행된 값부터 받는다. |
| 지속성 | **Transient Local** | 발행자가 보관한 값을 늦게 연결된 구독자도 받을 수 있다. 한 번 발행한 지도에 적합하다. |

## 6. 터미널 실습과 Python 패키지

**Talker → `/chatter` → Listener**: 발행자와 구독자를 별도 터미널에서 실행한 뒤, 다른 터미널에서 실제로 오가는 값을 확인한다.

```bash
ros2 run demo_nodes_cpp talker       # 터미널 1: 문자열 발행
ros2 run demo_nodes_cpp listener     # 터미널 2: 같은 문자열 수신
ros2 node list                       # 실행 중인 노드 확인
ros2 topic list                      # 토픽 이름 확인
ros2 topic echo /chatter             # 토픽에 들어오는 실제 메시지 확인
rqt_graph                            # 노드와 토픽의 연결을 그림으로 확인
```

- **직접 발행**: Talker를 끈 상태에서 `ros2 topic pub --once /chatter std_msgs/msg/String "{data: 'hello'}"`를 실행하면 Listener가 `hello`를 한 번 받는다. `--rate 10`은 초당 10회 발행한다.
- **거북이 원격 조종(teleoperation)**: `ros2 run turtlesim turtlesim_node`와 `ros2 run turtlesim turtle_teleop_key`를 별도 터미널에서 실행한다. 방향키를 누르면 `/turtle1/cmd_vel`로 속도 명령이 나가고, `ros2 topic echo /turtle1/pose`로 바뀐 위치와 각도를 볼 수 있다. 전진 속도와 회전 속도를 함께 주면 원을 그린다.
- **토픽과 서비스 비교**: 속도는 토픽에 계속 보내고, 특정 좌표로 한 번 옮길 때는 `/turtle1/teleport_absolute` 서비스를 호출한다. `ros2 topic info -v /turtle1/cmd_vel`로는 연결된 노드와 QoS를 확인한다.
- **colcon 워크스페이스**: `src/`에 패키지를 만들고 한 단계 위인 워크스페이스에서 `colcon build`를 실행한다. `build/`는 빌드 중간 파일, `install/`은 설치 결과, `log/`는 기록이다. 빌드 후 `source install/setup.bash`로 현재 터미널에 적용한다.
- **직접 만든 Talker와 Listener**: Python 패키지의 `setup.py`에서 `console_scripts`에 실행 이름과 `main` 함수를 연결한다. Talker는 타이머 콜백에서 `msg.data`를 채워 발행하고, Listener는 구독 콜백에서 받은 값을 출력한다. `rclpy.spin()`이 타이머와 수신 콜백을 처리한다.
