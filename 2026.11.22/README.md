
# 로보틱스 AI 2주차 | 2026.11.22 (일)

## 오늘 배운 내용

- 전날의 Talker·Listener 사이에 Processor를 넣어서 키보드 입력을 로봇의 2차원 좌표로 바꿨다.
- 세 노드의 실행 설정을 Python Launch 파일에 모아 명령 한 줄로 실행하는 방법을 배웠다.
- Service와 Action의 차이를 비교하고, 직접 정의한 메시지와 서비스로 두 정수의 합을 주고받았다. 마지막 실습 문제는 같은 구조를 로봇의 평면 이동에 적용하는 것이었다.

## 1. 키보드 입력을 좌표로 바꾸는 세 노드

| 순서 | 노드 | 받는 값 | 하는 일과 보내는 값 |
| --- | --- | --- | --- |
| ① | **Publisher** | 키보드의 W·A·S·D | 입력을 소문자로 통일하고, 방향 문자 하나를 `String.data`에 넣어 발행한다. |
| ② | **Processor** | 방향 문자 | 이전 좌표에 이동량을 더한 뒤, 현재 `[x, y]`를 정수 배열 메시지로 발행한다. |
| ③ | **Subscriber** | 좌표 배열 | `msg.data`에서 x와 y를 꺼내 현재 위치를 로그에 출력한다. |

- **토픽은 2개**: 첫 번째 토픽에는 방향 문자가, 두 번째 토픽에는 계산된 좌표가 흐른다. Processor 하나가 첫 번째 토픽의 구독자이면서 두 번째 토픽의 발행자다.
- **좌표 규칙**: 시작점은 `(0, 0)`. W는 y에 +1, S는 y에 −1, D는 x에 +1, A는 x에 −1을 더한다.
- **누적 예시**: W → W → D를 입력하면 `(0, 1)` → `(0, 2)` → `(1, 2)`가 된다. 두 번째 W에서 y가 2가 되려면 Processor가 이전 좌표를 기억하고 있어야 한다.
- **콜백 구분**: 타이머 콜백은 정해 둔 시간이 지날 때 호출되고, 구독 콜백은 메시지가 들어올 때 호출된다. 수업 코드에서는 방향을 받았을 때 좌표를 갱신하고, 타이머에서 저장된 좌표를 발행했다.
- **로그 확인**: 위치가 예상과 다르면 ‘입력한 문자 → Processor가 계산한 좌표 → Subscriber가 받은 좌표’ 순서로 본다. 어느 단계에서 값이 달라졌는지 확인할 수 있다.

## 2. Launch: 노드 3개를 명령 한 줄로 실행하기

- **저장 위치**: `src/<패키지명>/launch/`. Python 노드들이 들어 있는 안쪽 모듈 폴더와 구분해, `setup.py`가 있는 바깥 패키지 폴더에 `launch/`를 둔다.
- **실행 설정**: Python의 `generate_launch_description()`에서 실행할 항목을 정의하고 `LaunchDescription`으로 반환한다. 패키지명과 실행 이름은 각 노드를 `ros2 run`으로 실행할 때 쓰던 값과 맞춘다.
- **실행 순서**: 수업 예제에서는 `OnProcessStart`로 Publisher 프로세스가 시작되면 Processor를, Processor가 시작되면 Subscriber를 실행하도록 연결했다.
- **설치 설정**: `setup.py`의 `console_scripts`에는 **노드 실행 이름**을 등록한다. `data_files`에는 **Launch 파일**을 설치할 위치인 `share/<패키지명>/launch`와 복사할 파일을 적는다.

```bash
# Ubuntu의 Bash · 워크스페이스 최상위 폴더에서 실행
colcon build                             # 수정한 패키지와 Launch 파일을 빌드·설치
source install/setup.bash                # 현재 터미널에 새 설치 결과 적용
ros2 launch <패키지명> <Launch파일명>     # 꺾쇠 부분을 실제 이름으로 바꿔 여러 노드 실행
```

실행 이름이 자동완성에 뜨지 않으면 `console_scripts`를, Launch 파일을 찾지 못하면 `data_files`를 먼저 본다. 둘 다 수정 후에는 다시 빌드하고 현재 터미널에서 `source`한다.

## 3. Topic · Service · Action

| 구분 | 통신 흐름 | 수업 예시 |
| --- | --- | --- |
| **Topic** | Publisher가 발행하면 구독 중인 Subscriber가 받는다. | 방향 키와 현재 좌표를 계속 전달한다. |
| **Service** | Client가 한 번 요청하면 Server가 처리하고 한 번 응답한다. 서비스 자체에는 진행 피드백이나 취소 절차가 없다. | 엔코더 초기화, 현재 센서값 조회, 거북이 생성·초기화. |
| **Action** | Client가 목표를 보내면 Server가 수행하면서 진행 상황을 보내고, 끝에 결과를 반환한다. 수행 중 취소를 요청할 수 있다. | 로봇이 목표 지점까지 이동하거나 로봇 팔로 물체를 잡는 작업. |

- **Action의 세 부분**: ① **Goal**은 어디까지 갈지, ② **Feedback**은 지금 어디까지 왔는지, ③ **Result**는 도착했는지 또는 실패했는지를 나타낸다.
- **파일 확장자**: 토픽 메시지는 `.msg`, 서비스는 `.srv`, 액션은 `.action`에 구조를 정의한다. 이날 직접 구현한 통신 방식은 Service다.

## 4. 사용자 정의 인터페이스와 덧셈 서비스

**인터페이스**: 노드 사이에 어떤 타입의 데이터를 어떤 필드에 담아 보낼지 정한 형식이다. 수업에서는 형식을 정의하는 패키지와 계산을 수행하는 패키지를 나눴다.

| 위치 | 넣는 내용 |
| --- | --- |
| `custom_interfaces/msg/Num.msg` | 정수 하나를 담는 메시지. 필드 타입은 `int64`. |
| `custom_interfaces/srv/AddTwoInts.srv` | 요청은 `Num` 타입의 `a`, `b`. 응답은 같은 타입의 `sum`. |
| 인터페이스 패키지 | `ament_cmake` 기반. `CMakeLists.txt`에 생성할 `.msg`와 `.srv`를 등록하고, `package.xml`에 필요한 의존성을 적는다. |
| Python 노드 패키지 | `package.xml`에 `custom_interfaces` 의존성을 추가하고, 직접 만든 타입을 가져와 서버와 클라이언트를 작성한다. |

```text
custom_interfaces/Num a
custom_interfaces/Num b
---
custom_interfaces/Num sum
```

1. **서버**: `create_service()`로 덧셈 서비스를 열고 요청을 기다린다. 콜백에서는 `a`와 `b` 안에 들어 있는 정숫값을 더해 응답의 `sum` 안쪽 필드에 넣는다. `a`, `b`, `sum` 자체는 각각 `Num` 메시지다.
2. **클라이언트**: 터미널에서 받은 인자 두 개를 정수로 바꾸고, `wait_for_service()`로 서버가 준비됐는지 확인한다. 요청에 두 값을 채워 `call_async()`로 보낸다.
3. **결과**: `spin_until_future_complete()`로 응답을 기다린 뒤 합을 출력한다. 예를 들어 인자가 `2`와 `7`이면 요청은 두 정수이고, 돌려받는 값은 `9`다.

## 5. 마지막 실습 문제: 현재 방향으로 이동한 자세 구하기

- **메시지**: `RobotPose.msg`에 `float64 x`, `float64 y`, `float64 theta`를 둔다. x와 y는 현재 위치, θ는 로봇이 바라보는 방향이다.
- **요청**: `MoveRobot.srv`로 현재 자세와 이동 거리 한 개를 보낸다.
- **서버가 하는 일**: 현재 방향으로 요청받은 거리만큼 직진했을 때의 새 좌표를 계산한다. 출발 위치가 같아도 바라보는 방향에 따라 도착점이 달라진다. 회전 명령은 없으므로 θ는 유지한다.
- **응답**: 이동 후 자세와 성공 여부를 돌려준다. 수업의 가상 평면에서는 이동이 성공한다고 가정했다. 새 메시지와 서비스도 인터페이스 패키지의 `CMakeLists.txt`에 추가한다.
